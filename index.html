Part One

Encryption — reversible, if you hold the key

Encryption locks a message so only someone holding the right key can read it again. All three specimens below scramble the same way at heart; what changes is who's allowed to hold the key, and how many people can hold it.

FILE NO. 01

Caesar Cipher

Substitution · Classical · c. 50 BC

Shift every letter down the alphabet by a fixed number of places. Julius Caesar used a shift of three to send orders his enemies couldn't read at a glance. Break the shift and you break the whole message — there are only twenty-five to try, which is exactly why nobody serious has used this since antiquity.

FILE NO. 02

AES-256-GCM

Symmetric block cipher · NIST standard

Scrambles data in 128-bit blocks using one secret key, 256 bits long — long enough that guessing it is currently out of reach for any known attacker. GCM mode also seals the message with an authentication tag, so tampering is caught the moment someone tries to decrypt it. This is what's protecting your bank's website right now.

FILE NO. 03

RSA-OAEP

Asymmetric · Public-key · 2048-bit

Uses two different keys: a public one anyone can encrypt with, and a private one only you hold to decrypt. No secret ever has to travel between sender and receiver. The trade-off is size — a 2048-bit key with SHA-256 padding tops out around 190 bytes per message, which is why real systems use RSA to hand off a small AES key, then let AES carry the actual conversation.

Part Two

Hashing — one-way, on purpose

A hash takes a message of any length and returns a fixed-length fingerprint. Change one character in the input and the fingerprint changes almost completely — but there's no key involved, and no way back. A hash proves a message wasn't altered; it was never meant to hide it.

FILE NO. 04

SHA-256

Hash · SHA-2 family · 256-bit digest

Designed by the NSA and published by NIST as part of the SHA-2 family. Every input, from a single letter to a whole file, comes out as the same 256-bit digest. It's the standard behind TLS certificates, Bitcoin's block hashing, and most password-storage schemes — though passwords always run through a slow wrapper on top, never SHA-256 alone.

FILE NO. 05

MD5

Hash · Legacy · 128-bit digest · Broken

Once the standard checksum for files and passwords. MD5 is now considered cryptographically broken: two different inputs can be made to produce the same digest — a "collision" — in seconds on ordinary hardware. It's kept here because it's fast, simple, and a clean example of what a failed hash function actually looks like in practice.

Do not use MD5 anywhere security depends on it — password storage, file integrity against a real adversary, or signatures. It's shown for comparison, not for use.
